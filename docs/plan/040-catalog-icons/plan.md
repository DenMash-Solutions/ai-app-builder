# Catalog Icons — Lucide icons as a first-class catalog component — Implementation Plan

**Status:** implemented (2026-10-16 — full gate green; organic round 2 verified)
**Date:** 2026-10-15

## Goal

The model can place Lucide icons in generated UIs: an `Icon` component in the playground catalog (visible in `playgroundCatalog.prompt()`), rendered from a curated Lucide set, editable in the playground (insert picker + property form), and carried through preview/publish like any other element.

## Context (research findings)

- `@json-render/shadcn` ships **no icon component** (38 components, none icon-shaped) and no json-render package mentions icons — we define our own catalog component + registry impl.
- Catalog definition shape: `{ props: ZodObject, description, example, slots?, events? }`. `playgroundCatalog.prompt()` renders each as `- Name: { prop types with inline unions } - description` (current system prompt: 26.4 KB) — a `z.enum` therefore reaches the model **for free** as an inline union.
- The editor already understands enums: `lib/editor/editor.ts` derives `enum → options`, and `property-form.tsx` renders a Select — no editor work needed beyond the definition.
- `lucide-react@^1.51` exposes `icons` (1866 entries; `*Icon` aliases double it). Importing the full map would add ~1 MB to the client bundle and ~18 KB of prompt per generate request — curated explicit imports are tree-shaken instead (~150 icons ≈ tens of KB gz).
- Renderer behavior is safe for drift: unknown component type → warn + skip; our impl maps an unknown `name` → render nothing (ingest is non-blocking by design).
- `withStyleProps` merges the catalog's `className`/`style` onto whatever element the impl returns — works for a Lucide SVG (cloneElement).
- Press events follow a proven pattern: shadcn Button does `on("press") → emit()`; definition declares `events: ["press"]`.
- Testing pattern exists (`with-style-props.test.ts`): plain `bun:test` with a fake `ctx` — component impls are unit-testable without a DOM harness.
- **Live model run (gallery stress test, real Gemini through the MCP browser):** the enum pipeline worked end-to-end — the model's 50-icon state contained **47/50 valid enum names** (the 3 misses were curated-out but real lucide v1 exports), and it generated Previous/Next + `page` state. Failures that motivated the scope extension: (a) no filter primitive exists → the model invented an unsupported `$search` state expression and repeated over it → `RepeatChildren` called `.map` on a raw object → `TypeError` (contained by `ElementErrorBoundary`, grid blank); (b) `Button` is label-only → text-only pagination controls; (c) `wifi`/`battery`/`briefcase` missing from the curated set.
- json-render mechanics relevant to filtering: `$computed` resolves in **props and action params only** (single consumer in core) — **never inside `state`**; repeat `statePath` reads raw store state, so it must point at a real array. `JSONUIProvider` accepts `functions?: Record<string, ComputedFunction>`; the prompt auto-lists registered function **names** (args shape needs our own rule line). Input's impl emits only `submit` (Enter)/`focus`/`blur` — its def's `events` are `["submit","focus","blur"]`.

## Decisions

1. **One `Icon` component with a constrained `name` enum.** Props: `name: z.enum(keys)` (required, **kebab-case** — matches Lucide's own naming and the existing kebab-case copy-key convention), `size?: number` (px, **default 16** — impl falls back when omitted; Lucide's raw default of 24 is too chunky for inline UI), plus the shared `STYLE_PROPS` (`className`/`style`, same extension the shadcn definitions get). `events: ["press"]` so an icon can be an icon-button bound to actions (e.g. `switch_language`). `example: { name: "sparkles" }` so a fresh insert renders a real icon. The enum gives three things at once: guaranteed-valid model output, the editor's Select for free, and an inline union in the prompt.
2. **Curated set (~150), single source of truth.** `lib/playground/icons.ts` exports `LUCIDE_ICON_COMPONENTS: Record<string, LucideIcon>` with explicit named imports; the catalog enum is `Object.keys(...)` — prompt, editor, and renderer can never drift. Every key is validated against the installed `lucide-react` (v1.x renamed charts/alerts — names are generated from `l.icons`, not memory). Categories: arrows/navigation · actions/editing · files · status/feedback · media · communication · people · places/time · security · commerce/objects · charts · AI/sparkle (`sparkles`, `wand-sparkles`, `zap`, `rocket`). Adding an icon later = one line in the map.
3. **Wiring.** Definition added to `playgroundCatalog` components (extend with `STYLE_PROPS` like the shadcn defs); registry impl added in `registry.tsx` (wrapped in `withStyleProps`): look up `name` → render the Lucide component with `size`/`className`/`style`; wire `press` like shadcn Button; unknown name → `null`. `Icon` is a leaf (no slots) → it appears in the insert pickers automatically (`pickerItems()`, containers-first, alphabetical) with `examplePropsFor` defaults.
4. **No prompt-rule changes needed for `Icon`** — the catalog prompt carries the component line, description, and enum; `STYLING_RULES`/`i18nRules` stay untouched. *(Amended by D7: one search/filter rules section is added for the filter primitive — `Icon` itself still needs no rule.)*
5. **Button gains `leadingIcon`/`trailingIcon`** (open choice B adopted — user-selected): both `z.enum(LUCIDE_ICON_NAMES).nullable().optional()`, added exactly where the catalog transformation already extends Button with `STYLE_PROPS` (per-component extra-props hook). Because upstream's Button impl can't be injected into, **our registry overrides `Button`** with a copy of the small upstream impl (variant ternary, disabled, `emit("press")`), using the app's own `components/ui/button` and rendering the icon(s) around the label from the same `LUCIDE_ICON_COMPONENTS` map — an unknown/omitted icon degrades to no icon (never crashes). Prompt union + editor Select arrive automatically via the D1 mechanism; label-only usage stays the default, so existing specs are unaffected.
6. **Curation expansion — add `wifi`, `battery`, `briefcase`** (user-selected): evidence-backed by the live run (the only names the model wanted and the enum refused); all three are valid `lucide-react` v1 exports. Exactly these three — disciplined curation stays evidence-driven (D2).
7. **A real search/filter primitive for the model (`filterItems`)** (user-selected), entirely on our side:
   - `playgroundCatalog` registers `functions: { filterItems }` (`ComputedFunction = (args) => unknown`: `source` array + `query` + `fields[]` → case-insensitive substring match across the given fields; non-array source → `[]`). The prompt auto-appends `Available functions: - filterItems`.
   - Pass `functions={playgroundCatalog.data.functions}` to `<JSONUIProvider>` at **all three render sites** (playground, spec-page, live-page) so published specs resolve it too.
   - **Input `change` event:** the catalog transformation extends Input's `events` with `"change"`, and **our registry overrides the Input impl** (copy of upstream — `useBoundProp`/`useFieldValidation` are exported by `@json-render/react`; app's `components/ui/input`) adding `emit("change")` on input, so `on.change` is bindable (upstream only emits submit/focus/blur).
   - **One `STYLING_RULES` search/filter section** (the D4 amendment): bind the search field with `$bindState` to `/query`; **seed `state` arrays** (`/filtered-icons` starts as the full array — a repeat path must never point at an expression); filter with `on.change` → `setState("/filtered-icons", { "$computed": "filterItems", "args": { source: { "$state": "/icons" }, query: { "$state": "/query" }, fields: ["name"] } })`. The section documents the args shape (the prompt lists function names only).
8. **Pagination primitive + composition** (D8, option A — refined same-day as **D8r** after consulting the json-render skill): D5 made Previous/Next *look* right; nothing made them *work* — expressions have **no arithmetic**, and the repeat path must read raw state (no `$computed` there). Final shape:
   - `sliceItems({ source, page, limit })` → one page's items (a registered `$computed` function): the `page * limit` arithmetic lives **inside**; `page` clamped into `[0, maxPage]` so over/under-shooting buttons land on the edge page instead of a blank list; non-array source → `[]`; missing/non-positive `limit` → the whole source. It slices **`/filtered-items`** — the array the search pattern already seeds and rewrites — so search and pagination compose instead of forming two disconnected islands (organic round-1 finding). Nothing in the directive set does offset/limit paging, so this function stays.
   - **No bespoke `add` (D8r)**: the app-wide `$math` standard directive (`{"$math": "add", "a": {"$state": "/page"}, "b": 1}`; `"subtract"` for Previous) resolves inside action params (`resolveActionParam → resolvePropValue`, verified against installed v0.21.0) and is **already prompt-documented** — a second increment vocabulary would be redundant, so `add` was dropped from plan and code the same day.
   - **Search → re-page composition via `watch` (D8r)**: the search binding keeps the exact single D7 action (round-1 verified against the real model); an element-level `watch` on `/filtered-items` — array of bindings, each resolved against a fresh `getSnapshot()` (installed `on` **and** `watch` paths both do this) — resets `/page` to `0` and re-slices `/page-items`. Also already prompt-documented ("fires only on change, never on initial render").
   - **One `STYLING_RULES` pagination line**, hardened by organic round 1: seed `/page-items` with the **first page's actual rows** (it must be non-empty — the model seeded `[]` and got an empty grid); repeat reads `/page-items` (raw); Previous/Next = two ordered press actions (`$math` → `sliceItems`); **define the button elements** (round 1 referenced `prev-btn`/`next-btn` that were never defined → rendered nothing); the optional `watch` block for the search case; chevron icons via D5's `leadingIcon`/`trailingIcon`.

## Open choices — resolved 2026-10-15

- **A. Set size:** curated ~150 — **shipped as 159** (full 1866 rejected: ~1 MB bundle + ~18 KB/request prompt).
- **B. Button integration:** **adopted as D5** (`leadingIcon`/`trailingIcon`).

## Out of scope

Brand logos (Lucide deprecates them) · custom SVG upload · icon animations/spin (`animate-spin` via className already works) · searchable icon browser in the editor (plain enum Select is v1) · per-surface icon registries · ingest coercion of non-array repeat sources (crash-hardening option C — **not selected**; `ElementErrorBoundary` already contains it) · patching `@json-render/*` npm packages.
